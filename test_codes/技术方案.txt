保存机制失效：修改后保存按钮不可用，修改记录未正确同步

二、优化技术方案概述
总体架构目标
建立分层清晰、状态明确、恢复可靠的数据编辑系统，支持双表格模式的独立编辑和状态管理。

核心设计原则
分离关注点：原始表与扁平化表完全独立管理

状态可追溯：每次修改都有明确记录和版本

恢复自动化：重新进入时自动恢复所有编辑状态

保存可预测：保存按钮状态基于明确的修改计数

四、详细技术要求描述
要求1：数据状态分离管理
输入：用户选择sheet（原始/扁平化模式）

处理：

初始化该sheet的两种数据状态槽

加载对应表类型的数据

独立记录该表类型的修改

输出：清晰的UI状态指示（当前编辑的表类型、修改数量）

要求2：可靠修改记录
输入：用户在表格中编辑单元格

处理：

立即记录：{表类型, 单元格坐标, 旧值, 新值, 时间戳}

更新对应表类型的修改计数器

立即更新UI修改标记

输出：实时更新的修改计数，可用的保存按钮

要求3：状态自动恢复
输入：用户重新进入已编辑过的sheet

处理：

加载基础数据后，立即查询该sheet的修改记录

按表类型分别应用修改到对应表格

恢复所有修改单元格的视觉标记

输出：用户看到之前的所有修改都被保留

要求4：统一保存机制
输入：用户点击"保存草稿"或"最终保存"

处理：

只保存当前显示表类型的修改

成功后更新单元格标记为"已保存"

清除对应表类型的未保存修改计数

输出：明确的保存状态反馈，UI标记更新

五、数据结构规范
状态键命名规范
text
sheet状态键: `${pdfId}_${excelFile}_${sheetName}`
修改记录键: `${状态键}_modifications_${tableType}`
缓存键: `${状态键}_${tableType}_v${version}`
修改记录数据结构
javascript
{
  row: Number,          // 行索引
  col: Number,          // 列索引
  oldValue: Any,        // 旧值
  newValue: Any,        // 新值
  tableType: String,    // 'original' 或 'flattened'
  timestamp: Number,    // 时间戳
  saved: Boolean        // 是否已保存
}
